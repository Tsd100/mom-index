# 数据可信度 P0 实施计划

基于用户已确认的三项 P0 范围，直接实施，不增加部署和告警功能。

## 设计与验收

- 生产历史仅读取带完整来源证明的新记录。旧历史原样保留并计入未核验统计，不推断其真实性；模拟历史仅由显式演示命令写入 demo 子目录。
- 新记录附运行 ID、上海时区时间、采集页数、板块映射、规则源码哈希及 LLM 配置指纹（不含密钥）、样本 ID 摘要。不同口径不计算 Δ。
- 采样仍为股吧列表快照，不冒充“当天新发帖”。列表更新时间不当作发布时间；无法可靠解析的时间计入未知。少于 30 条有效样本、时间覆盖不足或超过 24 小时的样本占主导时不输出冷热判断。
- 运行日志保留各来源成功、失败、停用及部分成功状态；原始存档增加来源标签并隔离模拟帖。
- 看板显示质量、时间、来源、口径及旧记录隔离数量；页面刷新不等于重新采集。

## 执行顺序

1. 先写生产历史过滤、模拟隔离、样本新鲜度及跨口径 Δ 的失败测试；执行确认失败。
2. 实现 provenance 模块、历史读取与回测过滤、采集状态报告、管线接入及演示命令。
3. 接入卡片质量信息和过期提示，禁止旧静态 JSON 绕过新规则。
4. 用临时目录执行集成测试，保留既有本地数据；验证浏览器 DPR 1/2、空数据与异常状态。
5. 更新中文 README，审查差异中密钥与运行数据；提交并推送配置的 origin 分支。

## 测试与边界

使用 unittest，无需新增测试依赖。覆盖空采集、垃圾帖、模拟 ID、未知日期、日期边界、配置变化、旧历史及演示命令。离线夹具验证不等于数据源实时可用；网络采集与 NAS 部署状态分别报告。

## 完成本轮验证

- 15 项 unittest 通过；Python 编译、JS 语法、DOM ID、DPR 1/2 逐画布像素、移动端及异常场景检查通过。
- 独立只读审查发现的新鲜垃圾帖掩盖旧有效样本、演示覆盖正式报告、可选来源失败缺审计、后端过期信号等问题已修复并复核。
- 真实采集验证 12 板块默认 3 页：修正 span/cite 字段解析后收到 2278 条；3 板块质量合格、7 板块有效样本陈旧、2 板块身份核验页。核验页不当作市场冷清，也不尝试绕过。
- 本地服务 8503 的生产 JSON HTTP 200；原始历史文件无差异。运行数据、数据库与截图不提交。
- 当前只积累 1 个新口径日期，正式回测尚无可用前瞻收益；NAS 部署与告警仍在本轮范围之外。
