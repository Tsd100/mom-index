# 宝妈指数 NAS 每日采集与看板部署

默认每天上海时间 17:00 自动采集；首次安装启动立即采集一次。网页服务与采集服务独立运行，采集发生故障时网页继续提供上次已发布的快照，快照超过24小时会暂停情绪判断。每天包括周末都会检查采集，质量不足时如实显示。

离线包解决应用安装依赖；实际采集仍需要NAS能够访问东方财富和腾讯行情接口。默认关闭付费来源和LLM。

## 应用包内容

运行 `python nas-deploy-tool.py` 生成应用源码、Docker配置、固定版本Chart.js静态资源和Python3.12/Linux amd64离线wheels。生成位置为项目 `output/` 内的独立版本目录及ZIP。工具只按明确文件类型复制源码，不含本机数据库、历史记录、Cookie、`.env` 或配置目录。`manifest.json` 保存逐文件SHA-256。

**这不是完整镜像包。** 基础镜像 `python:3.12-slim-bookworm` 未包含，实际部署前要在NAS检查该镜像是否已缓存。已有同版本基础镜像时，依赖安装通过 `--no-index` 完成；没有基础镜像时须另行准备匹配架构的镜像，不能在NAS无法联网时直接宣称可构建。默认不安装Playwright浏览器环境，可选登录态来源仍需单独配置。

## 首次安装

1. 先核实NAS架构为x86_64、Compose版本、端口占用、目标目录及磁盘空间。现有项目升级须先确认原项目名、Compose覆盖文件、端口与全部挂载；不能直接套用新安装目录。
2. 将应用包解压到新的项目目录。校验manifest中的SHA-256。已有生产目录不能用应用包整体覆盖；保留原 `output/`、`.env` 和配置。
3. 按需要从 `.env.example` 创建 `.env`。`NAS_PORT=8503` 为看板外部端口，`COLLECTION_TIME=17:00` 为每日上海时间；`RUN_ON_STARTUP=0` 跳过额外的启动采集，当天已经错过的定时任务仍会补跑。凭据只保留在NAS本地配置中。
4. 确认基础镜像已存在，然后执行：

```sh
docker compose config --quiet
docker compose build --pull=false
# 仅在上一步成功后启动；不要在构建失败后继续启动旧镜像。
docker compose up -d --no-build --pull never
docker compose ps
```

访问 `http://NAS地址:8503/dashboard.html`。根路径也进入看板。网页 `/healthz` 验证服务存活，不代表上游采集成功。

## 持久数据与运行逻辑

- `output/data/`：原始SQLite、生产历史、逐次运行审计、行情批次、调度状态；仅采集服务挂载。
- `output/frontend/data/`：仅发布过滤后的 `dashboard_data.json` 和 `service_status.json`，网页服务只读挂载。网页路由白名单拒绝数据库、历史原件、目录列表和路径穿越。
- `web`：网页常驻，重启策略为 `unless-stopped`；Chart.js本地提供，不依赖浏览器访问CDN。
- `collector`：按每天指定时间运行。重启读取已持久保存的运行日期，同日已完成的定时任务不会重复触发；错过当天时间可补跑。单次任务40分钟超时，致命异常或全部来源采集失败时15分钟后重试，最多再试两次。部分来源失败或样本不合格显示部分完成，不伪造有效指数；仅帖子陈旧/时间未知/数量不足不会触发网络重试。
- 采集顺序：先更新有证明的前复权日线，再执行帖子采集、分析、质量检查和看板发布。行情失败仍会继续帖子采集。公开JSON采用临时文件后原子替换，网页不会读到写到一半的内容。
- 看板每5分钟读取数据和调度状态；读取网页不会触发采集。

查看采集日志：`docker compose logs --tail=100 collector`。日志按每个服务3份、每份10MB轮转。

## 旧部署升级和备份

先盘点原容器及实际挂载并保留原Compose/配置和镜像回滚标签；停止目标采集写入后，对全部持久挂载做一致性备份并校验。不能用本地小数据库覆盖NAS已有数据库。需要历史合并时，应在隔离副本中按来源/口径/业务身份补缺，并分别核对日期JSON和数据库记录数量。

旧 `CRON_SCHEDULE` 的“定时或网页二选一”入口已替换。新配置使用 `COLLECTION_TIME`；原端口和数据挂载应以现场盘点为准保留。升级服务拓扑前需确认旧服务容器已停止且不会继续写入同一数据库。

验收须分别记录：镜像构建、容器healthy、真实NAS网页、任务执行结果、原始库/历史保留和断开SSH后网页仍可访问。下一次17:00真实定时触发和连续多日运行必须后续观察，不能用一次本地测试替代。
